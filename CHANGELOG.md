# Changelog

## 2.1.0 — 2026-08-27

### Что изменилось

- **Надёжность очередей и сети.** Уведомления записываются в durable
  SQLite-очередь и не теряются при падениях. Добавлены повторные попытки,
  exponential backoff, jitter, ограничение скорости и корректная обработка
  Telegram `429`.
- **Логика бота.** `/start` нужен единожды: данные в SQLite переживают
  перезапуски. Повторный запуск требуется только при смене бота, утрате базы или
  блокировке пользователем. `TelegramBadRequest` больше не отключает личные
  сообщения — флаг снимается только при реальном запрете со стороны Telegram.
- **База данных.** Устранена квадратичная деградация большой очереди, добавлен
  partial index и исключены лишние записи пользователей в WAL. Реализованы
  проверенные backups, контроль целостности, безопасный restore и rollback.
- **Стабильность и изоляция.** Здоровье процесса отделено от доступности
  Telegram API, поэтому сетевые сбои не создают restart-loop. Добавлены watchdog
  зависшего event loop и минутное systemd-самовосстановление.
- **Безопасность контейнера.** Non-root запуск, read-only файловая система,
  ограничения CPU, RAM и PID, ротация логов, Docker secrets и зафиксированные
  версии зависимостей.
- **Транзакционные обновления.** Перед переключением сохраняются база, старый
  image, production-код и token. При неудачной проверке предыдущая версия
  восстанавливается автоматически.

### Установка

Развёртывание на поддерживаемом Linux-сервере выполняется одной командой:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/emmzde/call-you-bot/main/deploy/bootstrap.sh | sudo bash
```

Установщик добавляет Git и Docker, скрыто запрашивает token, запускает сервис и
настраивает self-heal и backups. CI публикует image для точного commit revision;
если готовый image недоступен, выполняется локальная сборка.

### Проверки

- 39 из 39 автоматических тестов пройдено.
- Ruff, Bandit, pip-audit, Trivy, ShellCheck, Hadolint и actionlint — без
  замечаний.
- 100 000 уведомлений — 3,924 секунды.
- 1 000 000 уведомлений для 100 000 пользователей — 24,839 секунды.
- Потери, дубли и повреждения базы не обнаружены.

Production-token должен работать строго на одном экземпляре сервиса.
Синхронизация SQLite-баз между независимыми копиями не предусмотрена.

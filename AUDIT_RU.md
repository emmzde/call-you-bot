# Production-аудит call-you-bot

Дата аудита: 27 августа 2026 года.

## Итог

Проект подготовлен к постоянной работе на одном Linux-сервере под `systemd` и
Docker Engine. Регистрация пользователя в боте не истекает через 24 часа:
нажать **Start** нужно один раз, а разрешение хранится в постоянной SQLite-базе.

Абсолютную доступность 100% не может гарантировать приложение на одном VPS:
могут одновременно исчезнуть сам сервер, его диск, сеть или Telegram API.
Проект автоматически закрывает сбои процесса, контейнера, обновления и локального
диска настолько, насколько это возможно на одном узле. Для контроля исчезновения
всего VPS обязательны внешний heartbeat и off-site backup.

## Что проверено и исправлено

- Разделены liveness приложения и доступность Telegram. Сбой Telegram больше не
  вызывает бесконечный restart-loop.
- Добавлен out-of-loop watchdog: зависший event loop завершает процесс, после
  чего Docker восстанавливает его.
- Уведомление сначала записывается в durable SQLite outbox и переживает crash,
  restart и пересборку контейнера.
- Исправлен квадратичный поиск следующей записи в большой очереди. Частичный
  индекс теперь используется самим планировщиком SQLite; это защищено тестом
  `EXPLAIN QUERY PLAN`.
- Повторное наблюдение неизменившегося пользователя больше не создаёт лишнюю
  запись в WAL на каждом групповом сообщении.
- Поиск разрешённых получателей выполняется статическим параметризованным SQL
  без динамической подстановки и без лимита в 999 параметров.
- `TelegramBadRequest` больше не лишает пользователя разрешения на личные
  сообщения: глобальный запрет выставляется только при `TelegramForbiddenError`.
- Добавлены согласованные SQLite-backups во время WAL-записи, проверка
  `quick_check`, безопасный restore, pre-restore backup и rollback.
- Обновление не останавливает старый контейнер во время подготовки образа,
  проверяет runtime и Telegram и возвращает предыдущие image и production-файлы
  при ошибке.
- Повторный install теперь сохраняет старый image и token, делает backup до
  переключения и также выполняет rollback при неудаче.
- Минутный systemd reconciler восстанавливает отсутствующий, остановленный или
  `unhealthy` контейнер и ограничивает частоту рестартов.
- Включены ежедневные проверенные backups, retention, опциональный отдельный
  mount и зашифрованный off-site restic.
- Контейнер работает без root, без Linux capabilities, с read-only rootfs,
  `no-new-privileges`, лимитами CPU/RAM/PID и ротацией логов.
- Python-зависимости полностью зафиксированы, а production-image привязан к
  точному Git commit. Готовый GHCR-image используется только при совпадении
  revision label; иначе выполняется локальная сборка.
- CI блокирует публикацию при падении тестов, Ruff, Bandit, ShellCheck,
  Hadolint, pip-audit, Trivy, Compose validation, image build или stress profile.

## Нагрузочные результаты

Изолированный тест не обращается к Telegram и проверяет реальную SQLite-очередь,
deduplication, закрытие/повторное открытие базы, drain, backup и restore.

| Профиль | Результат |
| --- | --- |
| 20 000 пользователей, 100 000 уведомлений, drain 25 000 | 3,924 с; 121 507 enqueue/с; 15 576 drain/с |
| 100 000 пользователей, 1 000 000 уведомлений, drain 100 000 | 24,839 с; без потерь, дублей и повреждения базы |

Цифры измерены локально и не являются обещанием скорости конкретного VPS, но
проверяют корректность алгоритма на очереди существенно больше обычной.

## Запуск

После публикации этой revision в ветку `main` новый сервер устанавливается одной
командой:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/emmzde/call-you-bot/main/deploy/bootstrap.sh | sudo bash
```

Скрипт запросит Telegram token скрытым вводом. Получить token без участия
владельца невозможно; сохранять его прямо в shell history небезопасно.

После первой успешной CI-публикации владелец репозитория один раз делает GHCR
package `call-you-bot` публичным. Если package пока private или registry временно
не отвечает, установка всё равно завершается, но собирает image локально.

Для защиты от полного исчезновения VPS заполните `/etc/call-you-bot/ops.env`:

- `MONITOR_HEARTBEAT_URL` и `BACKUP_HEARTBEAT_URL` от независимого мониторинга;
- `BACKUP_MIRROR_DIRECTORY` или параметры `RESTIC_REPOSITORY` для off-site копии.
